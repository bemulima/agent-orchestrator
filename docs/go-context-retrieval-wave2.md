and a deterministic 27-scenario corpus for Practice Runtime, Learning Planner and
TZ Planner. It does not admit Go Retrieval Profile v2 to production or authorize
service writes, contract materialization, model calls, or execution.

The ContextPack, RetrievalPlan and RoutingResult ABIs remain unchanged. Go AST
resolver v1 and the existing boundary owners/contract surfaces remain unchanged.

outbound adapter candidate. Ambiguous outgoing directories still require both
structured outbound metadata and bounded concrete net/http call syntax.

A repository can use `internal/application/usecase` for the canonical usecase
shape only if the existing profile already admits that target, its structured
`layers.usecase` or `layers.use_cases` declaration identifies that directory, and
parsed implementation/type declarations exist. The other canonical roots remain
required. Metadata and actual alternate source IDs participate in resolution.

ASCII classification keywords now require word boundaries. Russian stem behavior
is preserved. Leading read-only analysis actions recognize concrete architectural
responsibilities without treating business terms such as independent application
as an application layer. Dependent fragments, current-state statements, negative
instructions and conditions cannot gain scope through exact source names.
Concrete protocol lookup requires an admitted implementation call and literal or
module-bound constant; HTTP method registrations must match the requested method.
This is bounded syntax evidence, not a runtime registration or execution proof.

The three source snapshots were admitted through the production descriptor-safe
loader. Gold includes 497 content-hashed documents as flat text blobs and the
original independent scenario reports. Services with dirty working trees retain
DIRTY_SNAPSHOT provenance; their Git HEAD is not asserted to be their content.
The fixture contains 27 unchanged tasks, 62 Prepare anchors, 49 additional Expand
anchors and 56 required test anchors. Repository and test selection runs through
actual R1, source acquisition, Prepare and sequential Expand. Finding test source
never certifies a test execution in the target service.

The replay resource profile is bounded at 128K context tokens and 64K per facet.
Initial 32K and intermediate 64K runs remain separate diagnostic evidence; the
obligations were not removed to fit them. A failed transactional Expand preserves
its base pack, so the live verification ledger also records each attempt's status

All frozen explicit anchors and tests are found at the final resource profile.
Broader readiness remains PARTIAL: business-only requests can retain unresolved
R1 owner review, acquired routing evidence has explicit coverage limitations, and
